<Callout type="warn">
  The version history was reset. `0.0.1` is the first release of the reworked package. Releases `1.x`–`3.x` had incorrect provider integrations and callback checks that could be bypassed. Do not use them. See [What's New in 0.0.1](/docs/whats-new) for the reasoning and a step-by-step migration guide.
</Callout>

## 0.12.0

### Added

- **[Albaraka Türk provider](/docs/banks/albaraka):** non-3D sale, 3D Secure, refund, cancel, order inquiry and pre-authorization over Albaraka's Posnet JSON API. Bank-compatible order ids are generated when conversationId is omitted. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[Commission router](/docs/plugins/commission-router):** routes each payment to the cheapest eligible provider from your own rate tables, with an explainable quote, tie and share-cap policies, per-order overrides, and fallbacks only when no charge happened. Thanks to [@Enard52](https://github.com/Enard52).
- **[Currency conversion](/docs/plugins/currency-conversion):** convert prices before payments using Central Bank (TCMB) rates or custom FX providers, with kuruş-accurate basket allocation and refund rate locking. Thanks to [@Enard52](https://github.com/Enard52).
- **[Denizbank provider](/docs/banks/denizbank):** non-3D sale, 3D Secure (3D Model), refund and cancel over InterVPos. The callback hash is rebuilt from `HASHPARAMS`, and the bank's charge decides the result. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[EST Girogate](/docs/banks/est#girogate):** pay with iDEAL, Sofort, giropay, EPS, Bancontact, Przelewy24, Trustly and other alternative methods through the EST gate, with `girogate: { method, country }` instead of a card. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[More EST banks](/docs/banks/est#banks):** `akbankest` (Akbank's older virtual POS) and `halkbankmkd` (Halkbank Macedonia, with `MKD`) join the EST provider. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[Provider failover](/docs/plugins/failover):** automatically retry payments on backup providers during provider downtime or transient errors, with circuit breaker state management. Thanks to [@Enard52](https://github.com/Enard52).
- **[Fraud rules](/docs/plugins/fraud-rules):** `fraudRules()` counts payment attempts per IP, card, BIN, email or buyer, refuses card-testing runs, blocked BIN ranges and amounts over your limit before the provider is called, and exposes `FRAUD_BLOCKED` and `RATE_LIMITED` through `$ERROR_CODES`; counters are keyed by salted hashes and available under `better-payment/fraud`. Thanks to [@Enard52](https://github.com/Enard52).
- **[Garanti BBVA provider](/docs/banks/garanti):** non-3D and 3D Secure payments (3D, 3D_PAY), [GarantiPay](/docs/banks/garanti#garantipay), refund, cancel and order inquiry over the GVP XML API. 3D callbacks are verified from `hashparams` and confirmed with the bank. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[i18n plugin](/docs/plugins/i18n):** `localizedErrors` is now `i18n` and works like Better Auth's i18n plugin: `translations` with the built-in `locales`, `defaultLocale`, and `detection` strategies (`header`, `cookie`, `callback`) for each handler response. The old name still works and is deprecated.
- **[MCP server plugin](/docs/plugins/mcp):** Expose Better Payment as a Model Context Protocol (MCP) server for AI assistants. Thanks to [@Enard52](https://github.com/Enard52).
- **[NestJS adapter](/docs/integrations/frameworks#nestjs):** mount the payment handler in a NestJS controller on the Express or Fastify platform with `better-payment/nestjs`, without a `@nestjs/*` dependency. Thanks to [@Enard52](https://github.com/Enard52).
- **[Example shop](/examples/next-shop):** a runnable Next.js + Prisma storefront with a cart, server-side amounts, 3D Secure, payment events and refunds. Thanks to [@Enard52](https://github.com/Enard52).
- **[OpenAPI & Scalar Reference plugin](/docs/plugins/openapi):** Generate OpenAPI 3.1.0 schemas and serve an interactive Scalar API reference documentation page for payment handler endpoints. Thanks to [@Enard52](https://github.com/Enard52).
- **[PayTR Direct API 3D Secure](/docs/providers/paytr):** with `threeDSMode: 'direct'`, `initThreeDSPayment()` takes the card from your own checkout form and returns a signed Direct API form instead of PayTR's iFrame. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[Pending Payment Resolver](/docs/plugins/pending-resolver):** Recovers timed out payments by read-only provider status checks, emitting exactly one terminal event per payment even when resolvers run concurrently. Thanks to [@Enard52](https://github.com/Enard52).
- **[Captcha verification](/docs/plugins/captcha):** the `captcha` plugin verifies Cloudflare Turnstile, Google reCAPTCHA v3 or hCaptcha tokens server-side before a payment runs, so card-testing bots are stopped before they reach the provider. Callbacks and 3DS completions are never blocked. Thanks to [@Enard52](https://github.com/Enard52).
- **[QNB provider](/docs/banks/qnb):** non-3D sale, 3D Secure (3D Model and 3D Pay), refund, cancel and order inquiry over the PayFor XML API. 3D callbacks are verified with the ResponseHash and confirmed with the bank. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[QNBpay](/docs/providers/sipay#qnbpay):** QNBpay through the Sipay provider, with `qnbpay()` or `sipay({ brand: 'qnbpay' })`. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[Rate Limiting](/docs/plugins/rate-limit):** New `rateLimit` plugin throttles handler endpoints per route; the key defaults to an app-controlled source and only reads `X-Forwarded-For` when `trustProxy` is enabled. Thanks to [@Enard52](https://github.com/Enard52).
- **[Redaction (PCI DSS & KVKK)](/docs/plugins/redact):** mask cardholder data, CVV, and personal data in logs, events, and audit trails without altering provider requests. Thanks to [@Enard52](https://github.com/Enard52).
- **[Refund approval plugin](/docs/plugins/refund-approval):** Require manager review and approval for refunds and cancellations above a configurable amount threshold, preventing accidental or unauthorized large payouts. Thanks to [@Enard52](https://github.com/Enard52).
- **[Routing](/docs/plugins/routing):** picks the provider of each payment from your own rules (card family, card origin, amount, installment, health), with a dry-run `explain()`, deterministic 70/30 splits, audit listeners, and refunds that always reach the provider that took the payment. Thanks to [@Enard52](https://github.com/Enard52).
- **[Telemetry](/docs/plugins/telemetry):** OpenTelemetry-compatible spans and metrics for every provider call, with no card data in attributes and no dependencies. Thanks to [@Enard52](https://github.com/Enard52).
- **[3D Secure timeout](/docs/plugins/three-ds-timeout):** the `threeDSTimeout` plugin tracks initiated 3D Secure flows and expires the ones the customer abandons after a configurable delay. Each flow is re-checked with the provider first, so a late successful callback is never discarded, and `payment.threeDS.expireStale()` can be run from a cron job or a serverless schedule. Thanks to [@Enard52](https://github.com/Enard52).
- **[VakıfBank provider](/docs/banks/vakifbank):** non-3D sale, 3D Secure (MPI enrollment, then a VPOS authorization that takes the card and amount from VakıfBank's own 3D record), refund and cancel. `getPayment()` is not supported. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[Webhook forwarding plugin](/docs/plugins/webhook-forwarding):** Forward payment events to external microservices as HMAC-SHA256 signed webhooks with exponential backoff retries and card data sanitization. Thanks to [@Enard52](https://github.com/Enard52).
- **[Yapı Kredi provider](/docs/banks/yapikredi):** non-3D sale, 3D Secure through Posnet OOS, refund, cancel and order status. 3D payments are completed with the order from your records and confirmed with the bank. Bank-compatible order ids are generated when conversationId is omitted. Thanks to [@sizinajans](https://github.com/sizinajans).

### Fixed

- **[Failover](/docs/plugins/failover):** no failover after an HTTP 500, 502 or 504 answer, which can come after the card was charged, so a gateway error cannot charge the customer twice.
- **[PayTR basket encoding](/docs/providers/paytr):** Direct API payments now send JSON baskets instead of Base64. iFrame basket encoding and token signatures remain unchanged. Thanks to [@sizinajans](https://github.com/sizinajans).
- **[Writing plugins](/docs/guides/writing-plugins):** plugin `POST` endpoints refuse form bodies (CSRF) unless they set `acceptForm`, and a failing `onRequest` hook answers 503; [rate limit](/docs/plugins/rate-limit) no longer turns off silently when its store fails (`passOnStoreError` to keep the old behavior).
- **[Redaction](/docs/plugins/redact):** `fields` and `custom` add to the defaults instead of replacing them, cardholder name and provider secrets are masked by default, and identifiers and the 3D Secure page come back unmasked.
- **[Refund approval](/docs/plugins/refund-approval):** the approver of the HTTP endpoints comes from your session through `getActor`, never from the request body; cancellations and unreadable amounts wait for approval, and a double approval refunds once.

## 0.11.1

## 0.11.0

### Added

- **[`chaos` plugin](/docs/plugins/chaos):** injects declines, lost responses (`NETWORK_ERROR`) and delays into operations, so you can test how your application handles them. It refuses to run in `production` mode unless `allowProduction` is set.
- **[EST provider](/docs/banks/est):** İş Bankası, Ziraat Bankası, Halkbank, TEB and Şekerbank through one provider. Supports non-3D and 3D Secure payments (3D, 3D Pay, 3D Host) with hash ver3, plus refund, void and order status. 3D callbacks are confirmed with the bank.
- **[`notifications` plugin](/docs/plugins/notifications):** sends sales, refunds and failed payments to Slack, Discord, Telegram or your own channel, in the background and without card data. A failing channel never affects the payment.
- **[Sipay provider](/docs/providers/sipay):** non-3D and 3D Secure payments, 3D callbacks verified with Sipay's encrypted `hash_key`, full and partial refunds, cancel, status queries, pre-authorization, and BIN and installment queries. Verified end to end against the Sipay test environment.

## 0.8.1

### Fixed

- Framework adapters answer 413 for request bodies over 1 MiB instead of reading them into memory; change the limit with `maxBodySize`.
- Akbank: 3D Secure callbacks are confirmed with an order history query; a callback that does not match the order at Akbank is rejected.
- The HTTP handler accepts form bodies only for provider callbacks; other actions answer 415, so a form on another site cannot call them with the user's cookies.
- Errors passed to the logger no longer contain the provider request's body or headers (card data, credentials).
- iyzico: a failed 3D Secure result no longer carries a paymentId or conversationId taken from the callback request.

## 0.5.0

Plugins and typed payment events. **Breaking:** `betterPayment()` replaces `new BetterPayment()`, and providers are created with factories. See [Migrating to 0.5](/docs/guides/migration-0-5).

### Changed (breaking)

- `betterPayment({ providers, plugins })` replaces the `BetterPayment` class, and providers are created with `iyzico()`, `paytr()`, `akbank()` and `parampos()`. The `enabled` flag is gone.
- Any key of `providers` is a provider id; `payment.<id>` is typed per provider. `getEnabledProviders()` returns `string[]`.

### Added

- **[Plugins](/docs/concepts/plugins):** before/after hooks for provider operations, typed methods, handler endpoints and error codes. [Write your own](/docs/guides/writing-plugins) in a few lines.
- **[Payment events](/docs/concepts/events):** one typed listener for every provider and flow, emitted only for verified results.
- **[Localized error messages](/docs/plugins/i18n):** the first official plugin, in `better-payment/plugins`. Customer-facing messages in English and Turkish.
- **[Custom providers](/docs/guides/custom-providers)** with `defineProvider()`, and WebCrypto helpers for signing.

## 0.2.0

Pre-authorization and stored cards. Existing 0.1.0 code keeps working. Both features are tested against the real iyzico sandbox every night.

### Added

- **[Pre-authorization](/docs/payments/pre-authorization):** `authorize()` / `initThreeDSAuthorize()` block an amount, `capture()` charges it (partial capture supported) and `voidAuthorization()` releases it. iyzico, Parampos and Akbank; PayTR is not supported yet.
- **[Stored cards](/docs/payments/stored-cards):** save a card with `saveCard` during a payment, pay later with `storedCard: { customerToken, cardToken }`, and manage cards with `saveCard()`, `listCards()` and `deleteCard()`. iyzico and PayTR; Parampos and Akbank are not supported yet.
- [Handler routes](/docs/concepts/handler#routes) and browser client methods for both. Capture, void and the card routes require an `authorize` hook.

### Changed

- `PaymentRequest.paymentCard` is optional in the types; one of `paymentCard` or `storedCard` is required at runtime.
- The handler answers `400` instead of `500` when a provider does not support an operation.

## 0.1.0

The first feature release after the reset. Existing 0.0.1 code keeps working; behavior changes are listed under "Changed". The iyzico integration is now tested against the real iyzico sandbox every night.

### Added

- **[Unified error codes](/docs/reference/error-codes):** every failed result carries `code` (`INSUFFICIENT_FUNDS`, `CARD_DECLINED`, `THREEDS_FAILED`, `INVALID_HASH`, ...). `errorCode` keeps the provider's raw code.
- **[Request validation](/docs/concepts/configuration#request-validation)** before the provider is called. Invalid requests return `code: 'INVALID_REQUEST'` with every invalid field listed. Turn it off with `validate: false`.
- **[Parampos installments](/docs/providers/parampos#installments):** `installmentInfo()`, `calculatePaidPrice()` and `getInstallmentRates()` use your Param rates.
- **[Duplicate callbacks are processed once](/docs/concepts/handler#duplicate-callbacks-and-idempotency-key)**, and mutating handler routes accept an `Idempotency-Key` header. The `IdempotencyStore` is in-memory by default; use Redis or a database with several instances.
- `PaymentErrorCode` and `PaymentStatus` are exported from `better-payment/client`.

### Changed

- Request validation errors return `errorCode: 'VALIDATION_ERROR'`; `errorCode` used to be empty.
- Stricter public types, with no `any`: `rawResponse` and the handler bodies are `unknown`, and `onCallback` / `callbackRedirect` receive a `PaymentResponse`.
- `NETWORK_ERROR` messages name the transport error (`ECONNRESET`, timeout, ...).
- The published build is minified: about 19 kB gzip instead of 29.6 kB.

## 0.0.1

### Security

- **Parampos:** the 3D callback hash is verified only with the GUID from your configuration. Earlier versions read the GUID from the callback payload, which let anyone forge a successful payment.
- **Parampos / Akbank:** a 3D callback no longer counts as a successful payment on its own. Parampos finalizes with `TP_WMD_Pay`; Akbank uses the 3D_PAY model with an HMAC-signed result. A missing result code is no longer treated as success.
- **HTTP handler:** secure by default. By default it exposes only callbacks and card queries. Refund, cancel, payment lookup and subscription management require an `authorize` hook.
- **Retries** only re-send idempotent requests, so a timeout can no longer cause a double charge or double refund.
- Signatures are compared in constant time.

### Provider fixes

- **PayTR:** requests are signed with `merchant_key`, with `merchant_salt` appended to the signed data. `user_basket` is base64 JSON with TL prices. `merchant_oid` must be alphanumeric. `test_mode` follows sandbox mode. Refund amounts are in TL. Status queries use `/odeme/durum-sorgu`. Notifications are answered with plain `OK`. Secrets are no longer sent in request bodies.
- **Parampos:** uses `TP_WMD_UCD` / `TP_WMD_Pay`, comma-decimal amounts and the documented hash. Refunds and cancels use `TP_Islem_Iptal_Iade_Kismi2`, status queries `TP_Islem_Sorgulama4` and BIN lookups `BIN_SanalPos`. Made-up installment rates were removed.
- **Akbank:** rewritten against the Akbank Sanal POS JSON API.
- **iyzico:** Checkout Form and PWI results report the payment's own status (`paymentStatus`). 3DS completion requires `mdStatus=1`. `retrieveSubscription` uses GET.

### Breaking changes (compared with 3.x)

| Area | Before | Now |
|------|--------|-----|
| PayTR config | `apiKey`, `secretKey`, `merchantId`, `merchantSalt` | `merchantId`, `merchantKey`, `merchantSalt`, `testMode?` |
| Akbank config | `merchantId`, `terminalId`, `storeKey`, … | `merchantSafeId`, `terminalSafeId`, `secretKey` |
| Parampos config | also required `apiKey`/`secretKey` | `clientCode`, `clientUsername`, `clientPassword`, `guid` |
| `paymentId` (PayTR/Akbank/Parampos) | provider token / transaction GUID | your order id |
| Timeouts | `failure` | `pending` + `errorCode: 'NETWORK_ERROR'` |
| Handler | every route public, always HTTP 200 | opt-in routes, `authorize`, 422 on failure |
| Unsupported currency | silently TRY | error |
