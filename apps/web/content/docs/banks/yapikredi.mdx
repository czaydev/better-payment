Uses the Yapı Kredi Posnet XML API. 3D Secure runs through Posnet OOS: the card is sent to
`oosRequestData`, the bank's encrypted data is posted to its 3D service, and the result is
resolved with `oosResolveMerchantData` and charged with `oosTranData`. Both are signed with a MAC:
`base64(SHA256(XID;amount;currency;merchantId;base64(SHA256(encKey;terminalId))))`.

<Callout type="warn">
  Checked against the test environment with the test merchant from Yapı Kredi's guides: the order inquiry and the 3D data request (`oosRequestData`) are answered, and the MAC matches the guide's own sample. Non-3D sales are not open for that merchant, and its 3D page refused requests from a local test page, so no payment ran end to end. Test with a small amount before going live.
</Callout>

## Configuration

```typescript
import { betterPayment, yapikredi } from 'better-payment';

const payment = betterPayment({
  providers: {
    yapikredi: yapikredi({
      merchantId: process.env.YAPIKREDI_MERCHANT_ID!,
      terminalId: process.env.YAPIKREDI_TERMINAL_ID!,
      posnetId: process.env.YAPIKREDI_POSNET_ID!,
      encKey: process.env.YAPIKREDI_ENC_KEY!,
      // acceptedMdStatuses?: string[] (default ['1'])
      // baseUrl: defaults from mode (setmpos.ykb.com / posnet.yapikredi.com.tr)
    }),
  },
});
```

The order id (`conversationId`) has letters, digits or `_`: at most 20 for 3D Secure payments
(sent as the 20-character XID) and at most 24 for non-3D sales, left-padded with zeros. A
successful payment returns the bank's host log key as `paymentId`, which `refund()` and `cancel()`
take.

## Direct Payment (non-3D)

```typescript
const result = await payment.yapikredi.createPayment({ ...paymentRequest, conversationId: 'ORDER123' });
// result.paymentId is the host log key
```

## 3D Secure

```typescript
const init = await payment.yapikredi.initThreeDSPayment({
  ...paymentRequest,
  conversationId: 'ORDER123',
  callbackUrl: 'https://yoursite.com/payment/yapikredi/return',
});
// init.threeDSHtmlContent auto-submits the bank's encrypted data to its 3D service
```

Yapı Kredi POSTs `BankPacket`, `MerchantPacket` and `Sign` to `callbackUrl`. The MAC covers
your order id, amount and currency, which the callback carries only encrypted, so complete
the payment with the order from your own records. Spread the callback first so your values win:

```typescript
const result = await payment.yapikredi.completeThreeDSPayment({
  ...callbackBody,
  orderId: order.id,
  amount: order.total, // as in the payment request, e.g. '1.20'
  currency: 'TRY',
});
```

Because of this, Yapı Kredi callbacks are completed in your own route, not with the handler's
callback route. The result is confirmed with the bank:

- the resolved XID, amount and currency must equal your order, and the bank's MAC on the answer
  (`mdStatus;xid;amount;currency;merchantId;firstHash`) must match, otherwise it is rejected as `INVALID_HASH`;
- the card is charged with `oosTranData` only when `mdStatus` is accepted (only `1` by default; see
  `acceptedMdStatuses`), and the bank's answer decides. If the MAC on the charge answer
  (`hostlogkey;xid;...`) does not match, the result is `pending`: check it with `getPayment()`.

`paymentId` and `conversationId` are set only for a payment the bank approved.

## Refund & Cancel

```typescript
await payment.yapikredi.refund({ paymentId: hostLogKey, price: '50.00', currency: 'TRY', ip: '1.2.3.4' }); // return
await payment.yapikredi.cancel({ paymentId: hostLogKey, ip: '1.2.3.4' });                               // reverse
const status = await payment.yapikredi.getPayment('ORDER123'); // agreement, by order id
```

`getPayment()` takes your **order id**, as the bank's `agreement` inquiry does: it tries the non-3D
order id, then the 3D Secure one (`TDS_` + XID). A successful sale is `success`, or `cancelled` once
the order has a successful reverse or return; an order without a successful sale is `failure`.

<Callout type="info">
  BIN and installment queries are not supported: Yapı Kredi has none. `binCheck()` and `installmentInfo()` throw `NOT_SUPPORTED`.
</Callout>
