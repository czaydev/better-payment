Uses Vakıf Katılım's BOA VirtualPOS gateway with XML requests (`VPosMessageContract`). Requests
are signed with `HashData`: `base64(SHA1(MerchantId + MerchantOrderId + Amount + OkUrl + FailUrl +
UserName + base64(SHA1(password))))`, where requests without return URLs leave them empty.

<Callout type="warn">
  Not verified with a test merchant yet: Vakıf Katılım gives test stores on request. The gateway was reached through the provider: sale, 3D, provision, cancel and refund requests were read and answered for the made-up merchant (`MerchantNotDefined`; the provision got as far as decrypting the made-up `MD`). The cancel and refund hashes are not confirmed. Test with a small amount before going live.
</Callout>

## Configuration

```typescript
import { betterPayment, vakifKatilim } from 'better-payment';

const payment = betterPayment({
  providers: {
    vakifkatilim: vakifKatilim({
      merchantId: process.env.VAKIFKATILIM_MERCHANT_ID!,
      customerId: process.env.VAKIFKATILIM_CUSTOMER_ID!,
      username: process.env.VAKIFKATILIM_API_USER!,
      password: process.env.VAKIFKATILIM_API_PASSWORD!,
      // baseUrl: https://boa.vakifkatilim.com.tr/VirtualPOS.Gateway (test and live)
    }),
  },
});
```

All values come from Vakıf Katılım; the password is only used for the hash and is never sent.
The gateway has one address for test and live merchants.

`paymentId` is `<merchant order id>:<bank OrderId>`, since cancel and refund need both. Store it
as it is; `conversationId` is your order id.

## Direct Payment (non-3D)

```typescript
const result = await payment.vakifkatilim.createPayment({ ...paymentRequest, conversationId: 'ORDER123' });
// Non3DPayGate; result.paymentId is 'ORDER123:<bank OrderId>'
```

## 3D Secure

```typescript
const init = await payment.vakifkatilim.initThreeDSPayment({
  ...paymentRequest,
  conversationId: 'ORDER123',
  callbackUrl: 'https://yoursite.com/checkout/vakifkatilim/callback',
});
// init.threeDSHtmlContent is the bank's page that takes the customer to 3D Secure

// In your callback route, with the order from your own records
const result = await payment.vakifkatilim.completeThreeDSPayment({
  ...callbackBody,
  orderId: 'ORDER123',
  amount: '100.00',
  currency: 'TRY',
  callbackUrl: 'https://yoursite.com/checkout/vakifkatilim/callback',
});
```

`initThreeDSPayment()` sends the card to `ThreeDModelPayGate`, which answers with the page that
takes the customer to 3D Secure. A request the gateway rejects (for example an unknown merchant)
fails at once.

The callback carries `ResponseCode`, `MerchantOrderId`, `MD` and a `HashData` whose formula is not
confirmed, so it is not checked. When `ResponseCode` is `00`, the payment is charged with
`ThreeDModelProvisionGate` and the callback's `MD`, for the order id, amount and URLs from your
records, and the bank's answer decides. A callback for another order is rejected, and a failure
carries no ids. Use your own callback route rather than the handler's `complete-3ds` route.

## Cancel & Refund

```typescript
await payment.vakifkatilim.cancel({ paymentId, ip: '1.2.3.4' });                                   // SaleReversal
await payment.vakifkatilim.refund({ paymentId, price: '50.00', currency: 'TRY', ip: '1.2.3.4' });   // PartialDrawback
await payment.vakifkatilim.refund({ paymentId, price: '100.00', currency: 'TRY', ip: '1.2.3.4', fullRefund: true }); // Drawback
```

<Callout type="info">
  `getPayment()` throws `NOT_SUPPORTED`: no status query was found on the gateway. BIN and installment queries are not supported either.
</Callout>
