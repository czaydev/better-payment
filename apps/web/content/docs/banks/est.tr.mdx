İş Bankası, Ziraat Bankası, Halkbank, TEB ve Şekerbank aynı EST (Asseco NestPay) sanal POS altyapısını kullanır. Tek bir sağlayıcı, `est`, hepsini kapsar: `bank` bankanın canlı ortam adresini seçer ve tüm bankalar aynı ortak test adresini kullanır. Her bankanın örnekli kendi sayfası var:

| Banka | `bank` | Canlı ortam adresi |
| ----- | ------ | ------------------ |
| [Halkbank (EST)](/docs/banks/halkbank) | `halkbank` | `https://sanalpos.halkbank.com.tr` |
| [İş Bankası (EST)](/docs/banks/isbank) | `isbank` | `https://sanalpos.isbank.com.tr` |
| [Şekerbank (EST)](/docs/banks/sekerbank) | `sekerbank` | `https://sanalpos.sekerbank.com.tr` |
| [TEB (EST)](/docs/banks/teb) | `teb` | `https://sanalpos.teb.com.tr` |
| [Ziraat Bankası (EST)](/docs/banks/ziraat) | `ziraat` | `https://sanalpos2.ziraatbank.com.tr` |
| Akbank (eski sanal POS) | `akbankest` | `https://www.sanalakpos.com` |
| Halkbank Makedonya | `halkbankmkd` | `https://epay.halkbank.mk` |

<Since version="0.12.0" />

`akbankest`, Akbank'ın eski EST sanal POS'unu (sanalakpos.com) kullanmaya devam eden üye işyerleri içindir; Akbank'ın yeni JSON API'si ayrı bir sağlayıcıdır: [`akbank`](/docs/banks/akbank). `halkbankmkd`, Halkbank Makedonya'dır (Halk Banka AD Skopje); Makedon dinarı için `currency: 'MKD'` gönderin (`807` olarak iletilir). İki adres de XML API'ye cevap verdi (uydurma bir mağazayla), ancak gerçek bir mağazayla denenmedi.

## Bir uygulamada birden fazla EST bankası [#several-est-banks-in-one-app]

Her bankayı kendi mağaza bilgileriyle ayrı bir anahtar altında tanımlayın. Her anahtar, kendi callback adresi (`/api/pay/<key>/payment/complete-3ds`) olan ayrı bir sağlayıcıdır:

```typescript
import { betterPayment, est } from 'better-payment';

const credentials = (prefix: string) => ({
  clientId: process.env[`${prefix}_CLIENT_ID`]!,
  username: process.env[`${prefix}_API_USER`]!,
  password: process.env[`${prefix}_API_PASSWORD`]!,
  storeKey: process.env[`${prefix}_STORE_KEY`]!,
});

const payment = betterPayment({
  providers: {
    isbank: est({ bank: 'isbank', ...credentials('ISBANK') }),
    ziraat: est({ bank: 'ziraat', ...credentials('ZIRAAT') }),
    halkbank: est({ bank: 'halkbank', ...credentials('HALKBANK') }),
  },
});

await payment.ziraat.createPayment(request);
```

## Girogate [#girogate]

<Since version="0.12.0" />

Girogate, EST ödeme sayfasına iDEAL (Hollanda), Sofort, giropay, EPS, Bancontact, Przelewy24, Trustly, Multibanco, Boleto ve Alipay gibi alternatif ödeme yöntemleri ekler. Banka bunu mağaza bazında, anlaşmanızdaki yöntemlerle açar. Kart yerine `girogate` gönderin; ödemeyi banka aldığı için mağaza tipi `3d_pay` veya `3d_pay_hosting` olmalıdır:

```typescript
const payment = betterPayment({
  providers: {
    isbank: est({
      bank: 'isbank',
      clientId: process.env.ISBANK_CLIENT_ID!,
      username: process.env.ISBANK_API_USER!,
      password: process.env.ISBANK_API_PASSWORD!,
      storeKey: process.env.ISBANK_STORE_KEY!,
      storeType: '3d_pay', // or '3d_pay_hosting'
    }),
  },
});

const init = await payment.isbank.initThreeDSPayment({
  ...paymentRequest, // no paymentCard
  currency: 'EUR',
  conversationId: 'ORDER123',
  callbackUrl: 'https://yoursite.com/api/pay/isbank/payment/complete-3ds',
  girogate: { method: 'IDEAL', country: 'NL' },
});
// result.status after the callback: 'success', 'failure', or 'pending' for a method that settles later
```

`method`, `EST_GIROGATE_METHODS` içinden biridir; `country` müşterinin ISO 3166 ülke kodudur. Bazı yöntemler müşteri hakkında ek bilgi ister ve bunlar istekten alınır: Przelewy24, Zimpler ve Asya yöntemleri için e-posta (`buyer.email`), giropay, Dragonpay, eNETS, SingPost ve Tayland bankaları için telefon (`buyer.gsmNumber`), Entercash, Trustly ve AstroPay için müşteri numarası (`buyer.id`). Bunları `girogate` içinde değiştirebilirsiniz (`email`, `phone`, `consumerId`). Hepsi hash'e dahildir. Yöntemin çalıştığı para birimini kullanın (iDEAL için EUR, Przelewy24 için PLN, İsveç'te Trustly için SEK gibi).

Callback `3d_pay` gibi tamamlanır: onaylı bir ödeme sipariş durumu sorgusuyla doğrulanır. Sonradan kesinleşen bir yöntem (havale veya ödeme kuponu) `Response: Pending` ile dönebilir. ver3 hash'i değerleri kapsar ama alan adlarını kapsamaz; bu yüzden callback tek başına hangi siparişin beklemede olduğunu söyleyemez. Kendi kayıtlarınızdaki siparişi gövdenin içinde değil, ayrı bir argüman olarak verin: `completeThreeDSPayment(callbackBody, { orderId })`. Eşleşirse sonuç sipariş numarasıyla birlikte `pending` olur ve sonucu daha sonra `getPayment()` ile sorgularsınız. Verilmezse, örneğin yalnızca bankanın POST'unu ileten varsayılan handler üzerinden, sonuç numara taşımayan bir `pending` olur. Başka bir siparişe ait callback `INVALID_HASH` ile reddedilir; gövdeye eklenen bir `orderId` de, HASH gönderilen her alanı kapsaması gerektiği için reddedilir.

<Callout type="warn">
  Test mağazasında Girogate açık olmayan ortak EST test ortamında denendi: ödeme sayfası formu ve hash'ini (müşteri alanları dahil) kabul etti ve `Not a girogate merchant` cevabını verdi; bu bir başarısızlık olarak döner. Bir Girogate ödemesi uçtan uca denenmedi.
</Callout>
