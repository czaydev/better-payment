Ziraat Katılım runs the same PayFor platform as [QNB](/docs/banks/qnb), so `ziraatKatilim()` shares
QNB's provider. The differences are the hosts, the institution code (`mbrId`) and the callback hash.

<Callout type="warn">
  Not verified with a test merchant yet: no public test store is available. The test host was reached and answered as expected (unknown merchant), but no payment ran. Test with a small amount before going live.
</Callout>

## Configuration

```typescript
import { betterPayment, ziraatKatilim } from 'better-payment';

const payment = betterPayment({
  providers: {
    ziraatkatilim: ziraatKatilim({
      mbrId: process.env.ZIRAAT_KATILIM_MBR_ID!, // institution code (Kurum kodu)
      merchantId: process.env.ZIRAAT_KATILIM_MERCHANT_ID!,
      userCode: process.env.ZIRAAT_KATILIM_API_USER!,
      userPass: process.env.ZIRAAT_KATILIM_API_PASSWORD!,
      merchantPass: process.env.ZIRAAT_KATILIM_STORE_KEY!, // 3D key
      // secureType?: '3DModel' | '3DPay' (default '3DModel')
      // baseUrl: defaults from mode (payfortestziraatkatilim.cordisnetwork.com / vpos.ziraatkatilim.com.tr)
    }),
  },
});
```

All values come from Ziraat Katılım. `merchantPass` is only used for the hashes and is never sent,
and the API password is never put in the 3D form. `secureType` must match your merchant's 3D model.

`paymentId` is your order id: the `conversationId` you pass, or a generated id (letters, digits,
`-` or `_`).

## Payments

Non-3D sale, 3D Secure, refund, cancel and status work as with [QNB](/docs/banks/qnb), on the
`/MPI/Default.aspx` path. The XML API answers in `Key=Value;;` text, which the provider reads like
QNB's XML answer.

```typescript
const init = await payment.ziraatkatilim.initThreeDSPayment({
  ...paymentRequest,
  conversationId: 'ORDER123',
  callbackUrl: 'https://yoursite.com/api/pay/ziraatkatilim/payment/complete-3ds',
});

// In the callback route
const result = await payment.ziraatkatilim.completeThreeDSPayment(callbackBody);
```

## Callback Hash

The `ResponseHash` is checked with your merchant id and `merchantPass`:

- `3DModel`: `base64(SHA1(MerchantID + MerchantPass + OrderId + ResponseRnd))`
- `3DPay`: `base64(SHA1(MerchantID + MerchantPass + OrderId + AuthCode + ProcReturnCode + ResponseRnd))`

The `3DModel` hash does not cover the 3D result, so the payment is decided by the bank's answer to
`3DModelPayment`. A `3DPay` callback is confirmed with an order inquiry. A callback with an invalid
hash is rejected as `INVALID_HASH`, and `paymentId` is set only for a payment the bank confirmed.

<Callout type="info">
  BIN and installment queries are not supported: `binCheck()` and `installmentInfo()` throw `NOT_SUPPORTED`.
</Callout>
